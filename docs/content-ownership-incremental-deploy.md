# 内容创作与用户角色增量更新

1. 在虚拟主机控制面板先备份网站文件和数据库。
2. 在数据库管理工具中导入 `migrations/018_user_roles_content_ownership.sql`。重复导入是安全的。
3. 将 ZIP 上传到网站运行目录并解压，允许覆盖同名 `index.html`、`assets/`、`api/` 和 `app/` 文件。
4. 不要覆盖现有 `config/`、`uploads/`、`.htaccess` 或其他站点配置文件。
5. 在控制面板清理 PHP OPcache（没有该选项时等待几分钟或重启 PHP 版本）。
6. 访问 `/api/health`，返回 `schema: 018` 后再继续。
7. 登录后台的“用户账号”，为需要创作的账号设置 `ADMIN` 角色。至少保留一个有效管理员。
8. 使用该账号登录前台，打开“创作中心”创建或编辑自己的文章和项目。文章表单填写“专题名称”和“专题顺序”即可新建专题或加入已有专题；多篇文章填写相同专题名称即可归入同一专题。不同管理员或后台填写相同专题名（忽略首尾空格、连续空白和大小写差异）时，前台和后台会合并显示为一个专题并汇总文章。

文章和项目的作者会根据账号昵称动态显示。后台站点管理员创建的内容使用后台资料中的站点昵称，管理员账号创建的内容使用该账号昵称，无昵称时回退到邮箱。创作者接口由服务端校验角色和内容归属，不能通过修改 URL ID 编辑其他账号的内容。文章和项目标签会自动去重并写入共享标签表。

后台管理员和前台普通账号现在使用独立的 Session Cookie，可在同一个浏览器同时登录。更新后两类账号可能需要各自重新登录一次；后台退出不会再使普通账号退出，普通账号登录也不会清除后台登录。

本包是增量包，不包含 `config/`、`uploads/` 和数据库数据。部署前请确保 001-017 迁移已完成；本次必须导入 018 迁移。
