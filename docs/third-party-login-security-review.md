# 第三方登录安全设计与验收基线

本文约束 PHP 共享主机版本的微信、QQ、GitHub 第三方身份登录与绑定。当前版本不发送邮箱验证码，也不通过 OAuth 自动创建站内账号：用户先拥有并登录现有站内账号，再主动绑定第三方身份；已绑定身份以后可以用于登录。

## 信任边界与账号模型

- `user_accounts` 是唯一账号主体，OAuth 身份只是登录凭据。
- 身份归属只使用平台稳定标识，数据库必须唯一约束 `(provider, provider_subject)`。
- 昵称、用户名、头像和平台返回的邮箱只可作为展示资料，不能用于匹配、合并、换绑或修改站内 QQ 邮箱。
- 未绑定的 OAuth 身份不能创建用户，也不能产生正式用户 Session。
- 一个身份已属于用户 A 时，用户 B 的绑定必须失败，不能自动转移或合并。
- 绑定操作只允许由已通过密码登录的普通用户发起。管理员 Session 不等于普通用户 Session，也不能借此绑定普通用户身份。

## OAuth 事务

OAuth 发起端必须在服务端创建一次性事务，至少包含：

- 由 `random_bytes` 生成的不可预测 `state`；
- 固定的 `provider` 和 `intent`；
- 绑定操作发起时的 `user_id` 和当前 Session 关联信息；
- 经过校验的站内返回路径；
- 创建时间、过期时间和一次性使用状态。

回调必须先校验 provider、state、有效期和 Session 归属，再交换 code。state 无效、过期、重复使用或意图不匹配时立即失败。绑定回调还必须重新验证用户 Session 有效，并确认当前 `user_id` 与事务中的发起用户相同，防止 Login CSRF 和 Binding CSRF。

授权完成、拒绝授权和失败退出后都应消费事务。成功登录必须调用 `session_regenerate_id(true)`。OAuth 错误页面不得回显 code、state、token、secret 或底层异常栈。

## 重定向与服务端请求

- 回跳地址仅接受站内绝对路径：必须以单个 `/` 开头；拒绝 `//`、反斜杠、控制字符、协议和主机名。
- OAuth callback URL 来自服务端配置，不接受请求参数覆盖。
- 授权端、token 端和用户信息端是代码内固定的平台地址；后台凭据配置不能把请求目标改为任意 URL。
- 服务端 HTTP 客户端只能使用 HTTPS（本地测试例外不得进入生产配置），禁用自动跟随重定向，限制连接/总超时、响应体大小和协议。
- GitHub 使用稳定数值 `id`；QQ 使用官方 OpenID/UnionID；微信 OpenID 必须连同 AppID 作用域处理，获得 UnionID 时优先使用经过明确定义的联合标识。
- Scope 最小化。登录结束后不长期保存 access token 或 refresh token。

## 数据一致性与并发

- 绑定写入在数据库事务内完成，查询用户与身份归属时使用行锁或依赖唯一约束进行最终裁决。
- `(provider, provider_subject)` 唯一键是并发安全的最终防线；应用层 `SELECT` 不能替代唯一约束。
- 同一用户重复绑定同一身份应幂等成功；身份属于另一用户时返回冲突，且不得修改任何归属。
- 用户被禁用、冻结或 Session 版本失效后，绑定回调与第三方登录都必须拒绝。
- 解绑前确认账号仍保留密码或其他可用凭据。当前 `user_accounts.password_hash` 为必填时，解绑不会导致无登录方式，但仍应作为服务端不变量检查。

## 文章权限与缓存

`requires_third_party_binding = 1` 自动意味着必须有有效用户登录，而且该用户至少存在一个仍有效的 OAuth 身份。管理员后台预览权限可以单独保留，但不能把管理员浏览器的响应公开缓存。

以下路径必须在返回正文或静态资源前执行同一套服务端授权：

- `GET /api/public/articles/{id}`；
- `GET /api/public/article-sites/{...}` 的 HTML、JavaScript、CSS、图片和其他资源；
- RSS、Atom、搜索、列表、归档、系列、相关推荐、站点地图等内容发现路径；
- 任何新增预览、导出或移动端兼容接口。

列表可以展示标题和管理员明确公开的摘要，但不得包含正文。公开搜索不得用受限正文命中结果，以免形成内容探测 oracle。受登录或绑定保护的详情、错误元数据和静态资源响应统一使用 `Cache-Control: no-store`；公开缓存不得因某个已授权用户访问而保存受限正文。

权限执行顺序建议为：文章存在且已发布 -> 有效用户登录 -> 第三方身份存在 -> 独立文章密码已解锁 -> 返回正文。任一条件失败都不能返回 `content` 或 `staticSiteUrl`。

## Secret、日志与后台配置

- Client Secret 只保存在服务器配置文件或环境变量中，配置文件不进入 Git，权限限制为站点运行账号可读。
- 浏览器 API 只能看到 provider 是否启用、展示名称和授权入口，不能看到 secret、token endpoint 或原始配置。
- 后台保存 Secret 时空值表示保持原值，不能因前端返回的脱敏占位符覆盖真实 Secret。
- 审计记录 provider、intent、用户 ID、结果、时间、可信客户端 IP、User-Agent 和 request ID；不记录密码、code、state、token、Cookie 或 Client Secret。
- 审计详情继续经过 `app_audit_normalize_value()`，OAuth 新字段名也必须命中脱敏规则。

## 必须通过的验收矩阵

1. 已登录用户绑定未占用身份，绑定成功且审计完整。
2. 同一用户重复绑定同一身份，幂等返回且无重复行。
3. 用户 B 绑定已属于用户 A 的身份，返回冲突且归属不变。
4. 未登录用户发起绑定、回调绑定，均失败。
5. state 错误、缺失、过期、重复回调、provider/intent 不匹配，均失败且不写身份。
6. 攻击者发起的 OAuth 回调不能绑定到受害者 Session。
7. `returnPath` 为绝对 URL、协议相对 URL、反斜杠或控制字符时回落到安全站内路径。
8. 已绑定身份登录进入原账号，不创建用户、不修改 QQ 邮箱。
9. 未绑定身份尝试登录不创建账号，只提示先用原账号登录并绑定。
10. OAuth 平台超时、4xx/5xx、无效 JSON、缺少稳定 subject 时安全失败且不留半成品。
11. 两个并发用户绑定同一身份，数据库最终只有一个归属。
12. 登录成功后 Session ID 轮换；冻结、禁用或 Session 版本失效账号不能 OAuth 登录或绑定。
13. 未登录及未绑定用户直接请求受限文章详情时响应中没有正文和静态地址。
14. 未登录及未绑定用户使用已签名静态资源直链时仍被拒绝。
15. 已登录并至少绑定一种身份的用户可以读取；解绑最后一个第三方身份后立即失去对应文章权限。
16. RSS/Atom/搜索和公开缓存不能泄露受限正文。
17. 前后端和数据库升级不影响现有密码登录、管理员登录及历史文章默认权限。

生产启用前还需在微信开放平台、QQ 互联和 GitHub 后台登记完全一致的 HTTPS callback URL；微信、QQ 未完成资质审核或凭据未配置时保持禁用，不能用模拟接口代替。
