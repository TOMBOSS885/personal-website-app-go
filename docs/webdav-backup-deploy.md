# WebDAV 备份与可迁移加密热更新

本次更新包含两部分：

- SMTP 密码和管理员 2FA 密钥改为不依赖数据库名的新加密格式，同时兼容旧密文。
- 后台新增 WebDAV 远程备份、自动备份、保留数量、远程备份读取和输入密码恢复。

## 部署顺序

1. 备份当前网站文件和数据库。
2. 在 phpMyAdmin 按顺序导入 `migrations/020_webdav_backup.sql` 和 `migrations/021_webdav_progress.sql`。
3. 上传增量包并解压覆盖 `index.html`、`assets/`、`api/index.php`、`app/`。
4. 不要覆盖 `config/` 和 `uploads/`。
5. 清理 PHP OPcache，访问 `/api/health`，确认返回 `schema: 021`。

## WebDAV 配置

后台首页“站点健康与备份”中填写：

- WebDAV HTTPS 地址；
- 远程目录；
- WebDAV 用户名和密码；
- 备份密码（至少 12 位）；
- 自动备份间隔，范围 5–10080 分钟；
- 保留份数，范围 1–100。

WebDAV 密码和备份密码只以 AES-256-GCM 密文保存，服务器不会把它们返回给前端。远程恢复时必须再次输入备份密码，错误密码不会执行数据库或文件恢复。备份上传时会显示服务器实际通过 cURL 上传的字节数和百分比。

## 自动任务

虚拟主机需要配置 Cron/Web Cron，定期访问后台显示的接口：

```text
/api/webdav-backup/cron?token=后台显示的 Cron Token
```

建议每 5 分钟访问一次，由后台设置的“自动备份间隔”决定是否真正执行。每次任务会记录成功、失败、错误信息、最后备份和下次执行时间。WebDAV 不可用时只记录失败，不会删除已有远程备份，也不会影响本地导出备份。

## 跨主机恢复

不同主机配置相同的 WebDAV 地址、远程目录、账号和备份密码后，可以读取同一目录中的备份。恢复主机必须先部署当前代码并导入 001–021 迁移，再在后台“读取远程备份”并输入对应备份密码恢复。

本次加密升级会兼容旧 SMTP/2FA 密文；旧站完成热更新后访问一次后台健康接口，旧密文会自动转换为新格式。新备份会记录来源数据库名，恢复到不同数据库名时会自动重新加密旧密文。

旧版本生成、且没有记录来源数据库名的备份，跨数据库名恢复前应先在原服务器热更新后重新导出一次完整备份。数据库连接密码、PHP 配置和 Web Server 配置仍需在新主机单独填写。
