# 内容沉淀功能增量部署

本次更新同时修复静态前端文章黑屏：Vite 单文件 / `type="module"` 脚本在无 `allow-same-origin` 的 sandbox iframe 中不会执行，页面只剩下深色空壳。服务端会在下发 HTML 时把可降级的 module 脚本改写成经典脚本，已上传的文章不必重新打包。HTML 单文件不再受 2MB 硬限制，仍受后台 ZIP / 解压总量限制。

本次更新包含 RSS/Atom、文章专题导航、上一篇/下一篇、相关文章、文章归档/专题/精选发现入口，以及后台健康检查和可迁移备份。

同时包含前端背景控制更新：留言邮箱下方不再显示“仅后台可见”，图片背景可调壁纸透明度、背景模糊度和卡片透明度，可在毛玻璃与全透明模式之间切换，并移除了图片布局、位置设置。这些显示参数保存在访客浏览器中，不需要新增数据库字段或迁移。

## 部署顺序

1. 先备份网站根目录、`config/`、`uploads/` 和 MySQL 数据库。
2. 在 phpMyAdmin 中依次导入 `migrations/010_content_discovery.sql` 和 `migrations/011_article_discovery.sql`。两个脚本均可重复执行，不会删除或改写已有文章。
3. 上传补丁中的 `assets/`、`index.html`、`app/`、`api/index.php`、`migrations/` 和 `server-config/`，不要覆盖服务器上的 `config/`、`uploads/` 或 `setup.php`。
4. 将 `server-config/apache.htaccess` 或 `server-config/nginx-rewrite.conf` 同步到主机对应配置；Apache 还要把 `server-config/uploads.htaccess` 放到网站的 `uploads/.htaccess`。新增的 `/feed.xml` 和 `/atom.xml` 路由需要使用新规则。
5. 登录后台后打开 `/api/health`，确认返回 schema `011`。如果迁移未导入，接口会返回 `MIGRATION_REQUIRED`，不会再误报成功。再访问 `/feed.xml`、`/atom.xml`、`/archive` 和 `/series`。

完整备份需要主机启用 `ZipArchive` 和 `OpenSSL`，并将 PHP 的 `upload_max_filesize`、`post_max_size` 设置为大于备份 ZIP 大小。导入前必须先配置新服务器自己的数据库连接；备份会恢复数据库内容和应用密钥，但不会覆盖数据库连接参数。

## 使用说明

- 文章专题在后台“文章管理 → 新建/编辑文章 → 专题设置”中配置。可点击已有专题标签，也可直接输入新专题名称；同名文章会自动归组，“专题内顺序”数字越小越靠前，清空专题名称即可移出专题。
- 文章详情页会显示预计阅读时间、字数和顶部阅读进度，并支持“稍后读”、最近阅读和阅读位置恢复。这些数据只保存在当前访客浏览器的 `localStorage` 中，不上传服务器，也不需要账号或数据库迁移。
- 首页增加文章归档、专题系列、阅读清单以及精选/热门入口；后台文章编辑器可设置“精选文章”和精选顺序。如果没有设置精选文章，首页会自动回退展示热门文章。
- 顶部保留原来的“搜索”页面入口；博客栏目可在“全部文章 / 专题系列”之间切换，手机端也可从导航菜单进入归档、专题和阅读清单。
- Live2D 默认不会自动加载，必须由访客点击左下角按钮后加载；加载后在站内切换公开页面不会销毁或复位模型。
- 搜索页支持按文章、项目、留言和技能筛选，并会高亮匹配关键词。
- 后台“导出完整备份”会生成 ZIP，包含数据库全部表数据、所有 `uploads/` 文件和应用密钥快照；数据库与应用密钥使用 AES-256-GCM 加密，uploads 会按原文件打包，因此 ZIP 本身必须安全保存。
- 新服务器先部署代码并配置数据库，再在后台点击“导入完整备份”。导入会替换数据库和 `uploads/`，恢复后当前管理员会话失效，需要重新登录。备份密码无法找回，请与 ZIP 分开保存。
